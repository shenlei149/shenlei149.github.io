如果正确性无法妥协，那么面对 NP-hard 问题，我们只能选择精确但低效的算法。若 $\mathrm{P}\neq\mathrm{NP}$，这类算法在最坏情况下都至少以超多项式时间运行，我们能做的是尽可能快，至少要比穷举法快。

## Bellman-Held-Karp 算法
旅行商问题（`Traveling Salesman Problem`, `TSP`）是一个经典的 NP-hard 问题，穷举法需要遍历 $\frac{1}{2}(n-1)!$ 条可能的巡回来求解，这会得到一个比 $2^n$ 增长更快的时间复杂度。$2^n$ 不过是 $n$ 个 2 相乘，而 $(n-1)!$ 是 $n-1$ 个数相乘，其中绝大多数都远大于 2。斯特林近似告诉我们
$$n!\approx \sqrt{2\pi n}\left(\frac{n}{e}\right)^n$$
因此，穷举法的时间复杂度大约是 $\left(\frac{n}{e}\right)^n$，远远超过 $2^n$。在现代计算机上，$n!$ 的算法只能跑 $n=15$ 的规模，而 $2^n$ 的算法可以处理 $n=40$ 左右的规模，虽然提升不大，但是能处理的问题还是大了一些。

动态规划的核心是找到较小的子问题的集合，利用这些子问题的解来构建较大问题的解，最终得到原问题的解。假定有 $f(n)$ 个子问题，子问题最多需要 $g(n)$ 时间求解，花费最多 $h(n)$ 的时间处理额外的工作，那么算法时间最多是
$$f(n)\times g(n)+h(n)$$
对于 TSP 问题，预期 $f(n),g(n),h(n)$ 这三个函数中至少有一个是 $n$ 的指数级函数。

下面寻找最优子结构，也就是说把一个较大问题的最优解分解为若干较小子问题的最优解。假定顶点集合是 $V=\{1,2,\dots, n\},n\geq 3$，最优的巡回是 $T$，这个最优解如何从更小的最优解得到呢？$T$ 是从 1 出发回到 1 的路径，它一定是从一个顶点回来的，不妨令这个顶点是 $j$，假定我们知道了哪个顶点是 $j$，那么解就确定了。这样的 $j$ 有 $n-1$ 个：$j\in\{2,3,\dots, n\}$。假定 $C_{S,j}$ 表示从 1 到 $j$ 的最优路径（无环）的成本，其中 $S$ 是路径经过的顶点集合，那么
$$C_T=\min_{j\in\{2,3,\dots, n\}} \left\{ C_{V,j} + c_{j1} \right\}$$

继续往前推一步，一条从 1 到 $j$ 并且恰好访问每个顶点一次的最小成本路径 $P$ 是什么样的呢？如果最后一跳是 $(k,j)$，那么从 1 到 $k$ 的路径 $P'$ 恰好访问了除 $j$ 之外的所有顶点，并且是最小成本路径，也就是说 $P'$ 是恰好访问集合 $V-\{j\}$ 中每一个顶点的最小成本的从 1 到 $k$ 无环路径。使用反证法不难证明这一点。

那么我们可以得到递推式
$$C_{S,j} = \min_{k\in S-\{1,j\}} \left\{ C_{S-\{j\},k} + c_{kj} \right\}$$

Bellman-Held-Karp 算法就是利用上述递推式来求解 TSP 的最优解。它通过动态规划的方式，先计算较小子集的最优路径，再逐步构建较大子集的最优路径，最终得到整个顶点集合的最优巡回。算法伪码如下：
```
C = (2^(n-1)-1) * (n-1)     // two dimensional array to store C_{S,j} values
// base case
for j = 2 to n
    C[{1,j}, j] = c_{1j}

for s = 3 to n
    for each subset S of size s that contains 1
        for each j in S, j != 1
            C[S, j] = min_{k in S-{1,j}} (C[S-{j}, k] + c_{kj})

return min_{j in {2,3,...,n}} (C[V, j] + c_{j1})
```

下面分析算法复杂度。基本情况和最后的处理花费 $O(n)$ 的时间。子问题的数量最多是 $(2^{n-1}-1)\cdot(n-1)$，每个子问题的求解需要 $O(n)$ 的时间，因此总的时间复杂度是 $O(n^2\cdot 2^n)$。
